# P0.2 UI 修正：入口、加载态、文案

> 任务书只读。一个 commit：`fix(ui): install-first entry, loading states, trim copy`

## 1. 入口归位

现在"新建实例"在实例页，而"获取内容"页只有模组搜索。用户脑子里的顺序是
**先装游戏、再装模组**，所以入口要跟着这个顺序：

- 「获取内容」页改成两个顶层 tab：**安装游戏版本** / 获取模组（默认第一个）
- 「新建实例」按钮从实例页**移走**（实例页只留：导入整合包、刷新、列表）
- 实例页空状态的按钮 → 跳到「获取内容 → 安装游戏版本」

## 2. 首次打开的 Hero 卡

Hero 卡（主实例）在没有实例时是引导态，点「获取内容」现在落到 mod 页——错。改为：

- 无实例 → 点 Hero 的引导按钮，直达 **安装游戏版本** 向导第一步（版本列表已在加载）
- 有实例 → Hero 的按钮仍是「启动」

## 3. 版本点击后必须有反馈（现在的 bug）

点 `26.3` 之类的版本号后界面没反应，用户不知道点没点上。要求：

- 点击瞬间：该行进入选中态（背景 + 右侧 spinner），**立即**进入下一步页面骨架，不要等数据
- 拉 loader 版本期间显示骨架/skeleton（3 行占位），不是空白，也不是"加载中…"一行字
- 超过 8 秒没用响应 → 显示可读错误 + 「重试」「返回列表」
- 失败原因要具体：`maven.fabricmc.net 超时（8s）`、`该版本没有 Fabric 构建`
- 选中一个版本后再点另一个版本：直接切换，不叠加请求（取消上一个）

## 4. 文案：删掉 AI 味的解释句

现在的界面有一堆"你可以在这里……""帮助你更好地……"这类句子。规则：

- 空状态：**一句话 + 一个按钮**，不超过 20 字
- 每个分区标题下不加说明句；说明放进 tooltip 或帮助页
- 按钮 2–4 个字（`安装` `启动` `导入` `刷新` `打开文件夹`），不用"点击此处以…"
- 错误只写"发生了什么 + 下一步"，不写安慰话
- 全表扫一遍：`你可以`、`即可`、`轻松`、`只需`、`帮助你`、`强大的`、`丰富的` 全部删掉或改写

## 5. 一致性

- 加载态、错误条、空状态各只用一个组件（`Controls.kt` 里已有的），页面不许各写一套
- 所有异步动作三件套齐全：**loading / 成功反馈 / 失败可重试**，禁止"点了没反应"

## 验收

1. `build`/`test` 绿；一个 commit
2. 截图对比：获取内容页两个 tab、实例页（无新建按钮）、空状态 Hero 的三个入口
3. 录一小段（或三张连拍）：点版本 → 选中态 + spinner → 骨架 → loader 列表，全程无空白页
4. 断网（或把源指向不可达）后点版本 → 8 秒内出现可读错误 + 重试按钮（截图）
5. `grep -rn "你可以\|即可\|只需\|帮助你" composeApp/src/commonMain --include=*.kt` → 为空
