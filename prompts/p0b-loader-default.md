# 修：加载器默认选"原版"却仍然列 Fabric 版本

> 一个小 commit：`fix(ui): hide loader version list unless a mod loader is selected`

## 现象

点版本 → 进入加载器步：默认选中「原版」，但下面同时列着 Fabric 版本列表。用户看到的是
"我选了原版，为什么让我挑 Fabric 版本"。

顺带一个体验问题：既然默认是原版，这一步**根本不需要联网**，但现在仍然会去拉 fabric 版本。

## 改法

1. **默认选「原版」，且不显示任何加载器版本列表**；在原版分支下面放一行浅色说明：
   `原版不需要选择加载器版本`
2. 只有切到 Fabric / Forge / Quilt / NeoForge 时，才显示版本列表并开始探测
3. **切回「原版」要立刻隐藏列表**，并取消进行中的探测（沿用 generation 令牌 / cancelProbe）
4. 探测结果按 loader 分别缓存（Fabric 用现成的 loader 缓存；Forge/Quilt/NeoForge 各自 key），
   切走再切回不重新联网
5. NeoForge 不可达时：选项置灰 + 原因文案（这条已有，确认仍然生效）

## 为什么这样更好

- 默认路径（原版）**零网络**：点版本 → 立刻可继续，不需要等 12s
- 用户只在真正需要加载器时才触发网络请求
- 消除"选了原版还给我 Fabric 列表"的语义冲突

## 验收（缺一不算过）

1. `build`/`test` 绿；一个 commit；新增 ≥2 单测（原版分支不触发探测、切回原版隐藏并取消）
2. 真实鼠标（无 `-Dqa.*`）：点版本 → 加载器步显示「原版」选中 + 一行说明 + **没有任何版本列表**，
   且日志中**没有** fabric 请求（贴日志）
3. 切到 Fabric → 出现进度与列表（缓存命中应 <300ms；无缓存则走 3s/10s 阶梯）
4. 切回原版 → 列表立即消失、无新请求；再切回 Fabric → 立即出列表（缓存）
5. 截图：原版态、Fabric 态、切回原版态
6. 窗口级截图 + PID 断言
